# Flame Ring V2 P4.1 — 16 帧参考驱动的破碎 → 火流甩散

## 本阶段目标

本阶段只定型完整火环进入溃散后的连续性：火环不应先消失，再从随机位置生成一团火星；每个碎片必须能追溯到原始环段，从环面脱离后沿局部切线拉伸成火流，最后衰减为余烬。

依据本次提供的 16 帧参考图，参考序列中的视觉阶段为：

| 参考帧 | 视觉目标 | 代码中的处理方向 |
|---|---|---|
| 01–03 | 火焰沿椭圆环逐渐扩张、累积 | 保留现有 Reveal Curve、三材质 Ribbon 与火舌 |
| 04 | 环基本闭合，亮度和火焰轮廓达到峰值 | 完成传播后保持连续环体 |
| 05–09 | 满环稳定燃烧，外缘持续翻卷，亮核清晰 | 保持燃烧表现，不提前进入溃散 |
| 10 | 环体开始出现局部不连续，主体仍然易读 | 少量片段开始偏离原弧，几何与粒子位置保持对应 |
| 11 | 裂口和切向火流逐渐显现 | 片段位移加速，片段长度沿切线增加 |
| 12 | 更多环段脱离，部分火流向外甩散 | 同一裂解槽驱动三层几何、火星发射位置与运动方向 |
| 13 | 原始环形已明显破碎，只剩部分弧段和火流 | 移除已脱离的原环段，保留仍在生命周期内的火流片段 |
| 14 | 主要结构消失，剩余片段明显稀疏 | 全局末段衰减叠加片段自身淡出 |
| 15 | 少量暗红火星与短尾残留 | 停止密集发射，只保留少量在途火星和余烬 |
| 16 | 特效接近消失 | 溃散几何和新发射粒子都衰减至接近零 |

参考帧是视觉采样，不等于修改游戏内总时长。现有时序保持不变：5 tick 剑砍、6 tick 自传播、4 tick 满环燃烧、5 tick 溃散，总计 20 tick。

## 统一裂解模型

新增共享类：

`src/main/java/com/zzdzt/endfield_spellbook/spell/smoulderingfire/FlameRingBreakup.java`

- 使用固定的 32 个片段槽表示整圈。
- 每个片段的启始阈值和运动变化量由片段编号与实体 ID 确定，跨帧保持稳定。
- Outer、Body、Core 共用同一槽编号、相同的片段进度和原环段释放阈值，因此裂口位置保持对齐。
- 片段使用同一个切向位移、径向偏移和法向偏移计算。Renderer 与客户端粒子编排调用同一组数学函数。
- 片段在自身生命周期前段逐渐拉开，中段形成长火流，末段才淡出；另外使用全局后段衰减，使参考帧 14–16 的画面整体迅速变稀。

## 渲染实现

文件：

- `FlameRingRenderer.java`
- `FlameRingEntity.java`

Renderer 不再为 Outer、Body、Core 使用互相独立的裂解随机阈值。主环片段开始脱离时，会先沿共享的切向/径向/法向偏移移动；达到释放阈值后，原环段被移除。对应的片段继续被绘制，并逐渐拉长成火流。外焰、主体、炽核三层同时绘制这些片段，保持材质层次。

客户端粒子不再在溃散阶段每 tick 随机选择整圈位置爆发。粒子按同一 32 槽计划，从各片段的切向移动后位置发射；片段开始脱离时触发一次主火星，中段按稳定概率产生少量续流火星，尾段再发射稀疏余烬。

## 不变约束

- 不修改 `FlameRingCastCurve` 的常量、Reveal Curve 或总时长。
- 不修改施法、网络同步、伤害、消耗和冷却逻辑。
- 不修改 `PipelinePost`、`ArcaneFBO`、`FlameRingPass` 或 CA0 fallback。
- 不实施 P3 的通用后处理 Pass 或动态附件分配。

## 验收要求

源码与构建验收：

- 所有片段槽在各层一致；
- 三层裂口不互相错位；
- 不存在每帧随机重抽造成的闪烁；
- 共享位移函数被几何与粒子两侧共同使用；
- 时间轴仍为 20 tick；
- 完成 Gradle 构建并检查差异。

客户端验收：

- 参考帧 10 开始裂解，但仍能读出完整环形；
- 参考帧 11–12 的裂口到火流连续，不出现“断层式替换”；
- 参考帧 13 原环主体明显碎裂；
- 参考帧 14–16 快速衰减且没有整圈随机爆点；
- 施法初段、传播阶段、满环燃烧阶段与 P2 通过版本表现一致。

本提交只记录源代码改动和静态检查结果。未在真实 Minecraft 客户端中重放 16 帧参考之前，不应声称视觉验收已完成。
