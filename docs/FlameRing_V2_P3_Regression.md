# Flame Ring V2 — P3 整咒回归与性能收口

## 本阶段范围

P2 的服务端扇形命中已由项目验收确认。本阶段不调整施法、伤害、熔火资源、强化倍率或冷却；只收口视觉实体剔除、客户端追踪成本和回归流程。

## 源码改动

### 1. 视觉实体的距离与视锥剔除

- `FlameRingEntity` 不再无条件通过 `shouldRender(...)`；按环半径计算有效渲染距离，并扩大 `getBoundingBoxForCulling()`，使倾斜/近竖直的整圈不会因注册实体盒太小而提前被裁掉。
- `PhantomBladeEntity` 同样恢复距离剔除，按武器弧半径覆盖其完整运动包围盒。
- `PhantomBladeRenderer` 的视锥包围盒按实际弧半径扩展；强化焚灭半径扩大时不会仍使用固定的 4 格剔除边界。

### 2. 缩小短时视觉实体的客户端追踪范围

- `FLAME_RING` 与 `PHANTOM_BLADE` 的 `clientTrackingRange` 从 `64` 调为 `10`，避免远离技能有效观赏范围的客户端仍持续追踪短时特效。
- `FLAME_RING_ATTACK` 继续使用 `clientTrackingRange(0)`；命中控制器只在服务端处理，不向客户端复制。

### 3. 保持不变的玩法路径

- 时间轴仍由 `FlameRingCastCurve` 唯一控制：挥砍 4 tick、自传播 5 tick、满环燃烧 3 tick、溃散 4 tick，总计 16 tick。
- 合格斩击武器路径仍由服务端 `FlameRingAttackEntity` 对新揭示扇区结算；同次施法对同一目标只登记一次。
- 无合格斩击武器时仍使用 `SmoulderingFireSpell` 原有范围伤害回退。
- 原有熔火层数吸收/消费、强化焚灭倍率、ISS 伤害处理、施法消耗与冷却代码未在本阶段修改。

## 后处理降级审查

源码路径检查：

1. `post.pipeline=false` 或公共管线已失效时，`FlameRingRenderer` 走原有直绘路径。
2. 火环专属 `FlameRingPass` 初始化失败时，`FlameRingSnapshot` 使用 CA0 fallback；不把火环专属失败升级为公共管线失败。
3. 公共后处理运行期抛出异常时，管线会标记为 failed 并清空当前帧快照；后续帧由实体渲染器走直绘路径。

以上为源码路径审查，并非人为制造 Shader/FBO 故障后的游戏内实测。

## P3 验收清单

### 本地构建

- [ ] Windows：`.\gradlew.bat compileJava` 成功。
- [ ] 启动客户端无渲染器注册、Shader、FBO 或专用服务端类加载错误。

### 客户端后处理

- [ ] `post.pipeline=true`：火环三层材质、扭曲与 bloom 正常。
- [ ] `post.pipeline=false`：火环仍可见，使用直绘路径。
- [ ] 火环专属 Pass 不可用时：火环通过 CA0 fallback 可见，其他特效管线不受其专属失败影响。
- [ ] 第一人称、第三人称、低头/抬头和强化半径下，完整环面及剑体不在视锥边缘提前裁切。
- [ ] 远离施法位置后视觉实体按距离不再持续渲染；观察追踪范围收窄后近场旁观者仍可正常看到完整技能。

### 多人和玩法回归

- [ ] 两客户端联机：旁观玩家在有效追踪范围内能看到魔剑和火环；服务端命中不依赖客户端视觉实体。
- [ ] 同时由不同施法者施放：各自环/攻击控制器独立；单次施法不对同一目标重复结算。
- [ ] 持合格斩击武器时使用逐扇区命中；不持合格武器时仍走原有范围伤害回退。
- [ ] 熔火未满层与满层强化两条路径均正确；强化后层数按原逻辑消费，伤害/半径倍率不回归。
- [ ] ISS 伤害事件、抗性、火焰反馈与命中后附魔效果保持正常。
- [ ] 法术消耗与 18 秒基础冷却保持原样；视觉实体到期不会影响施法状态。
